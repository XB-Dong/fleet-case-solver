## 联调中发现并处理的问题

1. Windows 临时查询库文件被连接占用：显式关闭连接。
2. SQLite 批次写入锁冲突：复用连接并使用 WAL。
3. 小屏导航缺少可访问名称：补充 aria-label 与 title。
4. Flink JobManager 512 MiB 进程内存不足以满足默认堆外和 JVM 预算：调整为 768 MiB。
5. Doris 每批 500 行频繁写入造成 tablet version 达到 2000，低内存下 compaction 失败：扩大至每批最多 5000 行，FE 堆 768 MiB、BE 上限 2600 MiB、容器上限 4 GiB，完成合并后继续回灌并核对全量数据。未通过跳过失败批次伪造完成。
6. 源端重连会从头回灌：在独立 Redis DB 1 保存 Kafka 已确认批次游标，失败重试从该游标继续；确认与游标保存之间仍有至少一次重放边界。
7. 主机 3000 端口已有其他项目：Grafana 使用 3001，保留已有容器。
8. SQL 接口除了限制返回 200 行，还在真实数据库 SQL 中限制最多查询 201 行结果，避免缓冲游标先取回全部明细。

## 验证边界

- 未调用真实模型服务；模型模式仅有协议与模拟端点测试。本次交付无需模型 Key。
- 未验证生产规模吞吐、高可用、故障恢复可靠性、安全审计或端到端精确一次。
- Kafka/Flink 状态与实验 Doris 存储不是生产级持久化方案。源端游标依赖实验 Redis；Redis 丢失或确认边界重放可能影响窗口统计。明细采用唯一键覆盖。
- 运营看板和主要故障证据来自模拟器；MySQL/Redis 是桥接状态，Doris 是实际流处理结果。不能把它描述成真实车辆云控生产系统。
